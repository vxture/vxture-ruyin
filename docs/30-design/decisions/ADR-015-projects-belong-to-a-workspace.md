# ADR-015 项目必须归属工作区，无归属不是一种受支持的状态

- 状态：已接受
- 日期：2026-08-31
- 决策人：owner（2026-08-31 三问口径）
- 相关：ADR-007（对象层级）、30-contract-schema §18.5、
  60-operations/10-tech-debt.md TD-017

## 背景

ADR-007 定下层级：**租户 → 工作区（订阅主体）→ 已订阅产品 → 项目 → 任务**，
并指出「A 工作区的投标项目不该出现在 B 工作区里」。但实现里项目只是
`<dataDir>/projects/<id>`，与 `active_workspace` 毫无关系——切换工作区看到的
项目不变（TD-017）。

补上归属，绕不开一个冲突：

> **归属是登录态才有的东西，而项目可以在没有登录态时产生。**

产品首页有「暂不登录，先本地使用」这条路；`active_workspace` 只在登录后的令牌
claims 里才有。

## 决策

**不容许存在没有工作区的项目。** 这是不变量，其余三条都是维持它的手段：

### 1. 未登录不允许新建项目

不是把功能藏起来，是**这个动作缺少它的主体**。没有工作区，「建在哪儿」这个
问题没有答案，而任何替用户回答的做法都是编造。

界面上按钮置灰并说清缺的是什么，而不是让它没反应。

### 2. 不变量由类型持有

`createProject(contract, name, workspaceId)` —— 第三个参数必填。**不存在能产出
无归属项目的代码路径，也就没有以后要去审的路径。** 把归属做成事后补写的字段，
等于给自己留一个必须永远记得的规矩。

### 3. 存量记录是「待导入队列」，不是一种状态

attribution 之前写下的记录没有归属。处理方式：

- **单独分组呈现**，任何工作区下都看得见——过滤掉会让用户以为数据没了
- 配一个**导入到工作区**的动作
- 说清它是什么、以及怎么了结它

**不回填。** 回填是在替用户猜一个他没说过的事实；而**归错比不归更难发现**，
因为界面看起来完全正常。

**导入只填空白，不搬家。** 改变一个已有归属会把数据挪过订阅与权益边界，那是
另一件事、另一套后果，不该由一个「导入」按钮顺手做掉。这条在 runtime 里拒绝，
不在调用方守——下一个调用方不会记得。

### 4. 别的工作区的项目：隐藏，但报数量

只报**数量不报名字**。隔离要照做；同时「切一下工作区，项目全没了」在用户那里
和「数据丢了」分不开——而 §18.5 的「本地数据始终可访问、可导出」防的正是这种
误会。数量不跨租户（都是同一个用户自己的工作区），不构成泄露。

## 后果

- **会改变用户看到的东西**，这是 ADR-007 最直接的用户可见后果。
- **首页「暂不登录，先本地使用」的语义变窄了**：本地模式剩下的是运行环境本身，
  不含新建项目。文案须同步，否则是承诺了做不到的事。
- TD-017 回收。
- 一处实现陷阱记此备查：未登录时当前工作区是 `undefined`，而未归属项目的
  `workspaceId` **也是** `undefined`。只比相等会把「没有归属」当成「归属于
  没有」，同一个项目既算我的又算待导入，在列表里出现两次。已由用例钉死。
