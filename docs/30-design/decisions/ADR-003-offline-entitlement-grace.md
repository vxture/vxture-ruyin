# ADR-003 权益的受控持久化与离线宽限

- 状态：已接受
- 日期：2026-08-31
- 相关：平台《产品接入通则》C2（三条禁令）、30-design/30-contract-schema.md §18.5、
  ADR-001（执行点归属）

## 背景

通则 C2 的第一条禁令是**「不落产品库」**：权益只做短 TTL 缓存 + invalidate，
不做本地持久化副本。理由是「落了就有第二份真相，invalidate 管不到它」——
成立，但**该禁令默认调用方是常在线的服务端**。

Ruyin 是桌面客户端：必然离线，且**收不到 Webhook invalidate**（无公网入口，
见系统架构 E3）。严格照办的结果是关机重启后无网即全部产品不可用，连用户自己
的数据也打不开——与 §18.5「退订不得导致数据失联」的底线直接冲突。

## 决策

**受控持久化 + 离线宽限。**

| 状态 | 行为 |
|---|---|
| 在线 | 以服务端为准，拉到即覆盖快照。**快照永不与服务端竞争真相** |
| 离线 · 宽限期内 | 按快照放行，界面**明示「离线，权益为 ⟨时刻⟩ 的快照」** |
| 离线 · 超出宽限期 | 降级为只读：数据可访问、可导出，不可新建作业（§18.5 底线） |
| 重新联网 | 立刻拉取；判定为失效则**当场收回**，不等宽限期走完 |

持久化的是：订阅事实（`status` / `trial_ends_at` / `current_period_end` /
`cancel_at_period_end`）、销售轴（`tier` / `bundled` / `limits`）、**取得时刻**、
来源平台工作区 id。

**绝不持久化 `quota_pools[].remaining`。** 它每次别人调用都在变，而扣减发生在
Atlas（ADR-001），Ruyin 不在扣减链路上。过期的余额比没有余额更危险。

## 后果

- 这是对通则 MUST 的**带理由偏离**，理由是形态本质（客户端必然离线），
  不属于「迁移太贵」那一类，因此是合格豁免而非欠账。须在符合性登记中列明。
- 禁令的实质被保留：**联网即覆盖、永不落配额余额、陈旧状态不静默**。
- 另两条禁令（不做商业推断、容忍未知）**照办，不偏离**。
- 宽限期长度是商业判断，不由实现侧代定 —— 待决策。

## 备选方案

| 方案 | 为什么不取 |
|---|---|
| 严格不落盘 | 断网即全部不可用，与 §18.5 数据可访问底线冲突 |
| 永久离线可用 | 退订后可无限期使用，等于权益形同虚设 |
| 落盘且以本地为准 | 制造第二份真相，正是禁令要防的缺陷 |
