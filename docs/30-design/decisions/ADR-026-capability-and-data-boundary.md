# ADR-026 能力与数据的边界：智能体不自建能力面，能力来自 Runos，数据留在本机

- 状态：**§2 已接受**（owner 2026-09-15，逐条当场定）；**§5 旧设计的收口为提议**，owner 审定后再动
  技术债登记与契约
- 日期：2026-09-15
- **取代**：ADR-009（能力经业务产品的云端服务中转）
- **修订**：ADR-012（一级供给的来源）、ADR-018 / ADR-020（「产品分发」技能层的来源）、
  ADR-023（界面包的取回来源）
- 事实来源：vxture-runos origin/main `bd26817a`（原语只有 connector / skill / executor，`asset`
  不在生产范围；范围自陈「除模型推理之外」）；vxture-platform `#264` owner 答复；本仓
  `apps/local-host`（一项目一库 SQLCipher、`contract-fetch.ts` / `skill-distribution.ts` /
  `ui-fetch.ts` 三处都以 `RUYIN_CAPABILITY_BASE` 为来源）
- 相关：ADR-001（不直连 Atlas）、ADR-006（不门控不计量）、ADR-015（项目归属工作区）、
  ADR-025（能力调用两种路径）、RY-001 §07 #14 / #15

## 0. 一句话

**智能体不建服务端：它的定义随桌面包由平台分发到本机，它要的模型经平台到 Atlas，它要的
能力来自 Runos；它碰到的用户数据全部留在本机，不共享，单人使用。**

## 1. 为什么要改

ADR-009 当时选「每个业务产品自建云端能力面，由它持凭据调 Atlas」，理由是「不需要平台侧
任何改动」。落到今天：

- **一次都没通过。** bid 的云端能力面至今未建；装好的应用里模型回合走 `MockAIGateway`，
  智能体一次都碰不到本机能力（RY-001 §07 #8）。
- **每个智能体各建一套 = 重复建设**（owner）。能力平台本来就是为此而立的。
- 契约、技能分发、界面包三件事都顺着这条路线挂在「产品能力面」上，于是它们一起悬空。

## 2. 决定（owner，2026-09-15）

| # | 决定 |
|---|---|
| 1 | **智能体不自建能力面。** ADR-009 作废；`RUYIN_CAPABILITY_BASE` + `/products/{id}/capabilities/{cap}/turn` 这一套不再是目标形态 |
| 2 | **应用能力平台 = Runos。** 技能、远端连接器、沙箱执行，以及**平台级产品（数据平台、知识平台等）沉淀的资产**，经 Runos 服务多个智能体。走本机还是走云端按 ADR-025 |
| 3 | **模型回合经平台会话中转到 Atlas。** Runos 的范围不变（它不做模型推理）；桌面端仍不持任何下游令牌（#264） |
| 4 | **智能体的定义由产品提供。** 契约、技能包、界面包由产品设计；产品**针对桌面端运行打包**，登记到平台产品目录。**平台负责分发，ruyin 负责同步与本机存储** |
| 5 | **按需装到本机。** 用户可能订阅多个智能体：要在本机用的拉取安装，不需要的继续在云端使用 |
| 6 | **本机数据不出域。** 智能体需要的文档、数据连接器、生成的文档**全在本机**；智能体相关数据在它自己的库里（本机 SQLite，一项目一库加密），**不参与共享、单人使用** |
| 7 | **工作区之间的数据互通、知识互通是平台的工作，不是 ruyin 的。** 智能体需要哪些，由智能体设计和调用 |

### 2.1 出本机的只有两类调用

| 调用 | 去哪 | 出去的是什么 |
|---|---|---|
| 模型推理 | 平台会话 → Atlas | 这一回合的对话与上下文（推理传输，不是存储；敏感级别高的按契约 §9 要人确认） |
| Runos 能力 | 平台会话 → Runos（仅当 ADR-025 判定走云端） | 这次能力调用的参数 |

除此之外，**没有任何用户数据离开这台机器**：没有同步、没有备份上云、没有跨成员共享。

### 2.2 对 ADR-012 表格的更正

ADR-012 §背景那张表写「产品的智能（提示词、编排）不在本地，在产品自己的能力面」。按本
ADR 改为：**产品的智能随桌面包到本机**，由 Harness 在本机编排，模型经平台调用。直接后果
要说清：**提示词与编排在用户机器上可读** —— 这是「智能体不建服务端」的代价，产品设计时
应当知道。

## 3. 由此改变的来源

| 东西 | 原来从哪来 | 改成从哪来 |
|---|---|---|
| 模型回合 | 产品能力面 `/turn` | 平台会话中转（待平台提供） |
| 契约（ADR-012 一级） | 产品能力面 `GET /products/{id}/contract` | 平台产品目录的桌面包 |
| 技能「产品分发」层（ADR-018 / 020） | 产品能力面 `/products/{id}/skills` | 随产品包；共享技能经平台会话从 Runos 同步 |
| 界面包（ADR-023） | 产品能力面按摘要取回 | 随产品包；**契约钉摘要这一条不变** |
| 能力清单（ADR-020 §6.2） | —— | 经平台会话从 Runos 同步（平台 #339） |

契约钉摘要、按摘要校验落盘、多版本并存、离线沿用最后一份 —— 这些**本机侧的规矩都不变**，
变的只是字节从哪来。

## 4. 本机要做与平台要做

**本机（不依赖外部答复，可先做）**

1. 把「从哪同步」收成一个统一的来源接口，契约、技能、界面包三处都走它；今天的实现照旧，
   平台接口到位后只换实现。
2. 路由判定接入宿主工具执行（ADR-025）。
3. 首页「已订阅 · 本机未安装」卡加「安装到本机」，与「在线使用」并列；安装走现有
   `.ruyinpkg` 管线。

**平台 / Runos（走函件与 issue）**

1. 桌面会话可调用的**模型回合中转**（Atlas）。
2. 平台产品目录里的**桌面包分发**：按订阅列出可装的包、按摘要下载。
3. 签名根证书（已开 `#274`）—— 正式版装包的前提。
4. 能力清单与共享技能经平台会话同步（已开 `#339`）。

## 5. 收掉为同步预留的旧设计（**提议**，owner 审定后执行）

| 项 | 现状 | 提议 |
|---|---|---|
| TD-043 同步引擎（40-context-architecture §8 整章） | 零实现，登记为「等云端数据面」 | 转 **standing（有意不做）**：ruyin 不同步智能体数据 |
| 契约 §14 `sync` 键 | 有校验、无消费者 | 只收 `local_only`；下一次契约大版本删除 |
| 契约 §9 `context.types[].sources` 的 `cloud` | 可写，无通路 | 明确含义：**只指经 Runos 调用的云端能力或资产**，不指云端存储 |

## 6. 不变的

- 客户端零秘密；桌面端不持任何 `aud=<下游>` 令牌。
- Tool Gate 是第二层授权的唯一执行点，走本机、走云端都过。
- 权益门控只到产品级，不门控、不计量能力调用（ADR-006）。
- 项目必须归属工作区（ADR-015）—— 归属是边界，不是共享。

## 7. 备选方案

| 方案 | 为什么不取 |
|---|---|
| 维持 ADR-009，每个产品自建云端能力面 | 重复建设；至今未通 |
| 由 Runos 统一对外提供模型 | 要改 Runos 的产品范围（它的 ADR-003 排除模型推理）；owner 选平台中转到 Atlas |
| 用 Runos 的 `asset` 原语装智能体定义 | `asset` 是给平台级产品沉淀的共享资产用的，不是智能体定义（owner 澄清） |
| ruyin 做工作区成员之间的数据同步 | 越界：数据互通是平台的工作；ruyin 只解决数据不出域 |
