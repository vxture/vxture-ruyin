# ADR-013 成果落盘：结构化内容由 Runtime 渲染，字节回传为辅

- 状态：已接受
- 日期：2026-08-31
- 相关：ADR-006（skill 归 Ruyin）、ADR-008（模型归 Atlas）、ADR-011（框架边界）

## 背景

「产出本地文档」是核心需求之一，而标书最终要交的是 `.docx`——二进制。当前
工具执行器写 UTF-8 字符串，回合协议的 `content` 也是字符串：**文本能落盘，
字节落不了盘。**

三条候选：

| 方案 | 评价 |
|---|---|
| A. 工具参数带 base64 | **否决。** 工具参数来自提供方的 `tool_call`，也就是说字节会流经对话——一个 2MB 的文档变成 2.7MB base64 塞进上下文，成本与上限双双失控 |
| B. 「取回产物」引用 | 能力面返回引用，Runtime 下载并落盘。字节不进对话，任意大小可行 |
| C. Runtime 渲染 | 提供方返回结构化内容（标题 / 段落 / 表格），Runtime 渲染为目标格式并落盘 |

## 决策

**以 C 为主，B 为辅；A 否决。**

### 为什么渲染归 Runtime 而解析归 Atlas

这两件事看起来对称，其实不是：

- **解析** PDF → 需要理解、需要视觉模型 → **模型能力** → Atlas 补齐（ADR-008）
- **渲染** 结构化内容 → `.docx` → **确定性转换，不需要模型** → **技能** →
  Ruyin 提供（ADR-006）

而且渲染在本地更贴合「数据不出域」：**最终文档在本机组装**，不必先在云端生成
再传回来。

### 不违反框架边界

Runtime 定义的是**文档结构的形状**（标题、段落、表格），不是内容——就像
HTML 是形状而不是文章。按 ADR-011 的自查判据：这是在决定「有什么」，不是
「怎么说」。内容全部来自产品。

### B 作为辅路

产品若有自己的排版实现（特殊模板、专有格式），能力面返回引用，Runtime 下载
落盘。引用须限定作用域并带有效期。

## 后果

- 需要一个预制渲染技能与一种结构化文档表示；两者都是本仓的事。
- 渲染引入本地依赖——与「不为解析引入本地库」不冲突，因为那条针对的是**模型
  能力**，渲染不是。但它进的是签名客户端，选型要按此权衡。
- 工具执行器需要能写二进制，而不只是 UTF-8 字符串。
