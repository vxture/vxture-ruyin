# ADR-024 既有项目跟上产品的新版本：直接升，删了东西的才留在旧版

- 状态：**已接受**（owner 2026-09-12：「这个无需这么重，直接升级即可」）。提议稿是「人在
  项目里点了才升、放宽项逐条摆给人看」，owner 认为过重；定为**直接升**，只留一道不打扰人
  的保护（§2.2）
- 日期：2026-09-11（提议）/ 2026-09-12（改定并接受）
- 事实来源（每条都对过正文或代码）：
  `30-design/30-contract-schema.md` §6 / §8 / §9 / §11 / §12 / §18.4、
  `packages/runtime-core/src/project.ts`（`createProject` 快照契约、`load` 读快照）、
  `packages/runtime-core/src/harness.ts`（`TaskInstanceRecord.definition` 随实例冻结）、
  `apps/local-host/src/product-registry.ts`（`contractOf` = 生效版本，缺省最高版本）
- 相关：ADR-012（契约拉取与版本化落盘）、ADR-022（裁剪按快照）、ADR-023（界面跟快照走）、
  TD-048（本 ADR 要收的那一条）

## 0. 一句话

**产品库里的生效版本比项目的快照新，项目就直接升到它** —— 不用人点，不列清单。只有一种
情况不升：新版本**删掉了（或改窄了）这个项目在用的东西**，那时项目留在旧版，概览里写一行
原因。

## 1. 现状

项目创建时把当时的契约**快照**进项目库，此后状态机、任务、工具闸、`/bridge/*` 裁剪、产品
界面都按这份快照走。快照是对的 —— 产品升版不打断半截的工作；缺的是**升上去的路**：产品
发了 1.1，老项目永远停在 1.0，想用新任务、新界面只能新建项目、重新授权与绑定。

## 2. 决定

### 2.1 直接升

- **什么时候**：产品库的生效版本变了（契约拉取落了新版本、装了新包、切了生效版本）之后，
  守护进程把这个产品的项目逐个升上去；打开一个项目时也顺手看一眼（补上次没升成的）。
- **只往上**：生效版本比快照新才升。产品库切回旧版本（§18.4 的回滚）不会把项目退回去 ——
  新版本加进来的类型、任务可能已经产出了数据，退回去它们就成了孤儿。
- **等任务落定**：项目里还有没落定的任务就先不升，下一次再看。跑到一半的任务一边按旧快照、
  一边按新快照，谁都说不清它该听哪一份。
- **归档的项目不升**：它是只读的（契约 §6 的归档语义）；恢复之后下一次打开时升。
- 升了：换快照、更新 `productVersion` / `contractVersion`，审计记 `project.upgraded`（从哪版
  到哪版）；产品界面跟着换（ADR-023）；产品级凭据不作废（按项目 × 产品，不按版本）；发
  `project` 事件，工作台与产品界面都重问一次。

### 2.2 唯一的保护：删了（或改窄了）项目在用的东西，就不升

不信版本号标签、看实际差异 —— 一个标 minor 却删了东西的版本，照样不升。

| 契约段 | 算「删 / 改窄」 |
|---|---|
| `objects` | 删对象、删关系、换主对象 |
| `states` | 换挂载对象；删状态；删一条既有的转换 |
| `context.types` | 删类型；`required` false→true；删来源；改 `class` |
| `capabilities` | 删能力；改 `kind` |
| `tools` | 删工具；改 `category` / `provider` |
| `tasks` | 删任务；删它声明过的 `output_types` |
| `project.type` | 改 |

新增的一律放行；其余字段（文案、`input_schema`、默认权限、敏感度、`initial`……）的变化
随升级生效，**不拦也不列**（owner：「无需这么重」）。**工具闸的硬底线不受影响**：
`external_send` ≥ ask 以 `stricter()` 合并、不可配置，契约放宽不了它；用户在项目里设过的
工具策略照旧生效。

不升的项目，概览里写一行：「智能体已有新版本 X，但它删去了本项目在用的 …；本项目继续用
Y」。**如实说，不静默**：静默的话，用户会以为新版本的功能坏了。

### 2.3 检查器放在 `contract-schema`

`compareContracts(snapshot, next)` 是纯函数，放在**同构的 `contract-schema` 包**里 —— 云端
运行时升级项目用**同一个**判断（Same Validator, Any Runtime，§4）。

## 3. 不做的

- **major 迁移**：迁移声明的格式还没定（§19）。删了东西的版本只能给新项目用。
- **逐个确认、放宽项清单**：提议稿里有，owner 定为不要。

## 后果

- TD-048 实现落地后关闭。
- 契约规范 §18.4 补一段：规则由 `compareContracts` 执行，版本号标签只作参考。
- 产品方得到一个明确的约束：**想让老项目跟上，就只增不删**。
