## 0. 一句话

**产品智能体只认一套协议 —— Runos 协议；走本机还是走云端，由 Ruyin 按配置决定，对产品
无感。** 配置三档，**默认只许本机**；云端通路在平台补齐、开发完成之前不开放，任何配置
都收紧到本机并说明原因。

## 1. 现状（核实）

| | 事实 |
|---|---|
| 智能体今天怎么用能力 | 契约声明工具，模型回合交回 `tool_calls`，Ruyin 过 Tool Gate 后在本机执行 |
| 云端 Runos 怎么到 | ADR-009 / 020：经**产品自己的云端能力面**换票转来。bid 的云端未建，这条路**一次都没通过** |
| 桌面端能不能直接调云端 Runos | **不能，而且不该**。Runos 消费面只认 `aud=runos` 的 S2S 票；owner 在平台 `#264` 定：「ruyin 不该拿到 `aud=runos` 的令牌，任何形状都不该……要调下游时由平台换票」 |
| 本机能跑什么 | 232 条技能（Runos ADR-006：技能本来就在智能体运行时里执行）、27 台随包 MCP 服务器（6 台有启动规格）、用户 / 内网连接器（stdio、Streamable HTTP）、内建工具 |
| 本机不能跑什么 | 要第三方密钥的 8 台（密钥在 Runos 保险库，客户端零秘密）；Runos 自己运营的端点；Executor 沙箱（TD-005） |
| 本机能不能部署 Runos | 不能。Runos 是 NestJS + Postgres + Docker 沙箱的服务器形态，仓里没有任何本地 / 边缘部署设计（未核到反例） |

## 2. 决定（owner，2026-09-15）

### 2.1 一套协议，两条路

```text
                    ┌─ 本机 ─→ 兼容 Runos 协议的本地能力面（技能 / 随包服务器 / 连接器 / 内建）
产品智能体 ──Runos 协议──→ Ruyin 能力路由 ─┤
（discover/resolve/                         └─ 云端 ─→ console 会话 → 平台换票 → Runos /v1/mcp   〔未开放〕
 invoke/report_outcome，
 同一套 capability_id）
```

- **协议**：Runos 消费面的四个工具与 `capability_id` 词表（Runos 210 契约）。本机一侧实现
  同一套形状，而不是另起一套。
- **两条路都过 Tool Gate**。第二层授权（能不能碰这份数据）在 Ruyin，走云端也不例外
  （Runos ADR-008 自己承认这一层归调用方）。
- **同一个 `task_id` 贯穿两条路**：云端由 Runos 审计，本机由 Ruyin 哈希链审计，对得上账。

### 2.2 配置项

| 档位 | 值 | 含义 |
|---|---|---|
| 只许本机 | `local_only` | 只走本机；本机做不了就明确拒绝 |
| 优先本机 | `prefer_local` | 本机做得了走本机，做不了才走云端 |
| 优先云端 | `prefer_cloud` | 云端可用走云端，否则本机 |

- **粒度**：租户、工作区、能力。**越具体越优先**：能力 > 工作区 > 租户 > 默认。
- **默认：`local_only`**（owner 定）。
- **配置从哪来**：
  - 阶段 1：本机数据目录下的配置文件（`<dataDir>/capabilities/routing.json`），缺省即默认值。
    它只是策略，不含秘密，客户端零秘密这条规矩照常成立。
  - 阶段 3 起：平台下发（桌面会话可读的配置接口，届时向平台提出），平台下发的覆盖本机文件。

### 2.3 生效判定 —— 三层，顺序不能换

1. **能力本身的硬约束**（配置改不了）：要密钥的只能云端；内网连接器只能本机；本机没装的
   只能云端。
2. **配置**：按 §2.2 的优先级取出档位。
3. **可用性**：云端通路**未开放时视为不可用**；离线时云端不可用。

结果只有三种：`local` / `cloud` / `unavailable`，**每个结果都带原因**，界面与审计照原因说话。

**不许悄悄出域**：本机做不了时，只有配置明写 `prefer_local` 或 `prefer_cloud` 才可能走云端；
`local_only` 下一律 `unavailable`，绝不改道。改道意味着数据离开本机而用户不知道 —— 那正是
通则 P3「静默偏离比报错更糟」。

### 2.4 命名

面向用户可以叫 **Runos**，好理解；但凡出现，**必须注明「兼容 Runos 协议的本地能力面」**。
本机跑的不是云端 Runos 服务，不能让用户以为是。代码与文档里本机一侧叫「本地能力面」，
云端一侧叫「云端 Runos」，两个词不混用（通则 X-4 一词一义）。

## 3. 分阶段

| 阶段 | 内容 | 前提 |
|---|---|---|
| **P0** | **本机能力面保障**：技能、随包服务器、连接器、Tool Gate 与任务链路在本机真跑一遍，坏的修好 | 无 |
| **P1** | 路由框架与配置项落地（§2.2 / §2.3），默认 `local_only`；云端通路恒为未开放；界面显示当前档位与原因、带 §2.4 的说明 | P0 |
| **P2** | 平台补齐：会话中转换票的**调用**接口（不只是目录，`#339` 只要了目录）、调用归属（Runos 记到哪个产品）、路由配置下发接口 | 平台线 |
| **P3** | 云端通路开发：本机实现走 P2 的接口；本地能力面实现 Runos 协议四工具 | P2 |
| **P4** | 开放多端：云端通路视为可用，配置里的 `prefer_*` 真正生效 | P3 完成并验证 |

「本机能完成的先行」（owner）：P0、P1 不依赖任何外部；P2 起才需要平台。

## 4. 与既有 ADR 的关系

- **ADR-020 §3「经产品云端中转」**：P2 之前不动。P2 若按「平台会话中转」落地，届时修订
  ADR-020 §3，并请 owner 确认替换（本 ADR 不预先替换 —— 平台的接口形状还没定）。
- **ADR-009 模型推理**：不在本 ADR 范围。本 ADR 只管 Runos 那一侧的能力调用。
- **ADR-020 §6.2 能力清单**：清单是 P1 界面与 P3 发现（`discover`）的共同数据来源，
  清单接口（`#339`）到之前，本机只列本地能力面。

## 5. 不变的

- Ruyin 永不持有 `aud=runos` 或任何下游令牌；客户端零秘密。
- 权益门控只到产品级；Ruyin 不门控、不计量能力调用（ADR-006；Runos ADR-023：能力不是计费单位）。
- Tool Gate 是第二层授权的唯一执行点。
- TD-005：OS 级沙箱之前，契约不收执行类工具；本地能力面不跑技能脚本。

## 7. 备选方案

| 方案 | 为什么不取 |
|---|---|
| 桌面端直连云端 Runos（持 `aud=runos` 票） | owner 在平台 `#264` 否决：持不住密钥的客户端能铸下游票，拿到安装包的人就能拿到同样的能力 |
| 在本机部署一份 Runos 服务 | Runos 是服务器形态（Postgres、Docker 沙箱）；第三方密钥不下发，搬下来也调不了要密钥的能力 |
| 维持「每个产品的云端能力面各自中转」为唯一云端通路 | 至今一次没通；每个产品各建一套；与「对产品无感」相反 |
| 默认 `prefer_local` | owner 定默认 `local_only`：云端通路未验证之前，默认值不该允许任何出域的可能 |
