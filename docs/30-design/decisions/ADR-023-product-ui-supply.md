# ADR-023 产品界面从哪来：契约**钉摘要不钉地址**，界面包按内容寻址取回、缓存在本机

- 状态：**已接受**（owner 2026-09-11：「合并，继续」，回的是「接受 ADR-023 吗」那一问）。
  方向此前已由 owner 选定（片三时的题二，三选一选了 C：「契约里钉一个 UI 包 +
  sha256，像组件那样取回并缓存到本机」）；本 ADR 把 C 落成可实现的形状
- 日期：2026-09-11
- 事实来源（每条都对过正文或代码）：

- 相关：ADR-012（两级供给，契约拉取为主）、ADR-022（产品接入面的信任边界，本 ADR
  是它「后果」末条留下的题）、TD-012（签名信任锚）

## 0. 一句话

**契约里只写界面包的 sha256，不写地址；界面包从产品自己的能力面按摘要取回，校验、
解包、按摘要落盘。界面是可选的，坏了等于没有界面，不等于产品不可用。**

## 1. 现状（2026-09-11）

片三 a 把**装载**这一侧做完了：每个产品一个 origin（`<产品>.localhost:<端口>`）、
sandbox iframe、CSP（`connect-src 'none'`、`frame-ancestors` 只许工作台）、接上片二
的桥。观察台用一个仓内测试包实测过：产品代码读不到会话令牌、摸不到父窗口、走桥
回 200。

缺的是**来源**：`product-ui-server` 从 `<dataDir>/product-ui/<产品>/index.html` 出
文件，而**没有任何东西往那里放文件**。真实程序里所有产品都是没有界面的产品。
契约里今天没有一个字段说「这个产品有界面、是哪一份」。

## 2. 前提：界面是可选的，缺省没有

工作台已经能通用地渲染任务、检查点、上下文、成果；控制权界面一律归 Runtime
（接入指南 §6.3）。很多产品可能根本不需要自己的界面。所以：

- 契约**不写** `product.ui` = 这个产品没有自己的界面。这是缺省，不是缺陷；
- 界面出了任何问题（取不回、摘要不符、包不合规）→ **这个产品暂时没有界面**，
  产品本身照常可用，工作台照常渲染。**不因为界面拒收整份契约。**

## 3. 决定

### 3.1 契约钉摘要，不钉地址

```yaml
contract: "0.2"
product:
  id: bidproposal
  # …… 其余不变
  ui:                     # 可选。不写 = 没有自己的界面
    sha256: 3f2a…（64 位小写十六进制）
```

**只有一个字段。** 入口固定为包根下的 `index.html`，不开 `entry` 之类的配置项 ——
少一个可配置项就少一条要校验的规则、少一种路径穿越的写法。

**为什么不写地址**（即当时的方案 B 为什么不选，外加一条）：

- 写 URL、iframe 直接加载 → 离线就没有界面，破坏本地优先；每次都在沙箱里跑一份
  实时拉来的远程代码，今天和昨天跑的可能不是同一份；
- ADR-012 的一级供给有一条：「不新增一处存主机名的地方」。契约里写 URL 就是新增
  了一处，而且是**产品作者**可写的一处。

### 3.2 取回走契约的同一条通路，按摘要寻址

```text
GET {能力面基址}/products/{productId}/ui/{sha256}
```

与契约拉取（`GET {基址}/products/{id}/contract`）**同一个主机、同一个凭据、同一个
运行时设置**，没有扩大信任面。

**按摘要寻址而不是按版本**，得到三件事：

- **不可变**：同一个地址永远是同一份字节，可以永久缓存；
- **§18.3 那条「同版本内容变了」的难题在这里不存在**：内容变了摘要就变了，是另一个
  地址；
- **多个产品版本共用同一份界面**时自然去重（只改契约不改界面的 patch 版很常见）。

### 3.3 管线（顺序即安全顺序）

```text
取回 → 尺寸上限 → sha256 与契约一致 → zip 护栏解包 → 入口存在 → 按摘要原子落盘
```

- **尺寸上限先于一切**：边收边计数，超了当场断开，不先收完再说；
- **摘要校验先于解包**：摘要对不上的字节**一个都不解开**。解包是这条线上最危险的
  一步，只对已经确认是契约所钉的那份字节做；
- **zip 护栏复用 `pkg.ts`**（拒绝路径穿越 / 绝对路径 / 加密条目 / 未知压缩方法 /
  zip64 / 超限尺寸与条目数）—— 那是本仓攻击面最集中的一处，已经自持实现、逐条可审，
  不再写第二份；上限比产品包**更紧**，数字在实现时定并钉测试；
- **落盘位置**：`<dataDir>/products/<productId>/ui/<sha256>/`，与契约共用产品库；
  先解到同级临时目录、整体 `rename` 过去，半截的目录永远不会被当成可用。

**什么时候取**：契约拉取成功之后**紧接着**取，不等第一次打开。桌面必然离线，第一次
打开时才发现取不回，就是在最需要的时候没有。

### 3.4 装载哪一份：**项目快照里的那一份**

项目创建时快照当时的契约（已实现），界面跟着快照走：

```text
http://<productId>.localhost:<端口>/<sha256>/index.html
```

- **界面与裁剪它的契约必须是同一份。** 守护进程按项目快照裁剪 `/bridge/*`
  （ADR-022 §3.2）；装新版界面去对旧版快照，界面会去调快照里没声明的面 —— 被拒，
  而用户看到的是「界面坏了」；
- **origin 仍然是每个产品一个，不是每个版本一个**。产品自己的存储跨版本保留，与
  云端「一个产品一个二级域名」同一个模型；摘要只出现在路径里；
- **不回退到别的摘要**。快照钉的那份不在或校验不过，就是没有界面 —— 拿另一个版本
  的界面顶上，等于绕开了 3.4 第一条。

`GET /projects/:id/product-surface` 相应地从「看文件在不在」改为「看快照钉了哪份、
那份在不在」，并在 `available: false` 时带上**原因**（没声明 / 还没取回 / 校验不过），
工作台据此决定说不说、说什么。

### 3.5 信任：界面包的信任 = 契约的信任，**不需要等签名**

ADR-012 的划线是：本地可执行技能要签名，因为那是**以用户的系统权限**跑第三方代码。
界面包也是可执行代码，但它跑在另一个位置：

| | 本地技能 | 产品界面 |
|---|---|---|
| 跑在哪 | 用户的操作系统里 | 浏览器沙箱里，自己的 origin |
| 能碰文件 / 网络 | 能 | **不能**：CSP `connect-src 'none'`，没有令牌，够不到 Local API |
| 唯一的出口 | — | postMessage → 桥 → 产品级凭据 → **守护进程按契约裁剪** |
| 能做的事的上限 | 系统权限 | **契约声明的范围**（闸门在守护进程，ADR-022） |

所以界面包能做的事**不超过契约已经允许的事**，而契约本身就是从同一条通路来的。
摘要把界面钉在契约上，界面的信任就等于契约的信任 —— 不依赖 TD-012 的根证书。

**这个结论有前提，写死在这里**：它成立是因为沙箱 CSP 不许产品界面出网。哪一天要
放宽（比如许产品界面直连自己的服务），**这一节要重开**，不是顺手改一行 CSP。

副作用也写清楚：**界面包必须自足** —— 字体、图片、脚本全部在包里。远程资源一律被
CSP 挡住。这对本地优先是好事，但产品作者要知道。

### 3.6 契约版本升到 `0.2`

`schema.ts` 里 `product` 是 `additionalProperties: false`。于是**不升版本**的后果是：
今天装着的运行时拿到一份带 `product.ui` 的契约，报的是 L1「product 有未知属性 ui」
—— 用户看到的是一句莫名其妙的结构错误，产品整个加载不了。

升到 `0.2`，同一件事在旧运行时上报的是 R1「契约版本 0.2 不受支持」—— 结果一样是
不能用，但**说的是真话、指向该做的事**（升级 RUYIN）。新运行时同时接受 `0.1` 与
`0.2`；带界面的产品把 `runtime.minimum` 设到第一个支持它的版本。

**现在做最便宜**：stable 还没发，装机的只有 beta。

### 3.7 新增一条规则 R17（编号沿稀疏编号，不复用）

| 规则 | 内容 | 层级 |
|---|---|---|
| R17 | `product.ui` 只能出现在 `contract ≥ "0.2"` 的契约里；`sha256` 为 64 位小写十六进制（L1 pattern）。**取回的字节与 `sha256` 一致、包根有 `index.html`**是加载期校验，**不过则该产品没有界面，不拒收契约**（§2） | L1 / L2 / L3 |

`ruyin lint` 管得到 L1 / L2；L3 那一半 lint 看不见（字节不在契约里），与 R16 的
「在不在本机清单里是 L3」同一种处境。

## 4. 不变的

- 沙箱、每产品一个 origin、CSP、桥、产品级凭据 —— ADR-022 与片三 a 的全部，一行
  不动；
- 契约拉取为主、产品包为辅（ADR-012）。**二级产品包要带界面时，带的是同一个
  界面包文件**（包内一个条目、同样受 CHECKSUMS 覆盖、同样要与 `product.ui.sha256`
  一致）—— 一份字节，两种承载。§18.1 那张图里的 `ui/` 目录届时改为这个文件；
  **本 ADR 不实现二级这一侧**，等第一个需要二级供给的产品；
- 「Same Package, Any Runtime」（60 §4.2 第 3 条）的落点：云端加载的就是这份按
  摘要取回的界面包 —— 本地与云端是同一份字节，不存在本地特供版。

## 5. 分片（每片都能在没有真实产品、没有能力面的情况下验证）

**3b-1 · 契约**：`contract: "0.2"`、`product.ui`、R17、测试夹具。`products/bidproposal`
那份内置夹具**不加界面**（TD-033：它得看起来就是它本来的样子）；带界面的夹具只进
测试与观察台。

**3b-2 · 取回与落盘**：`ui-fetch`，接在契约拉取后面；用一个假能力面验：摘要不符一个
字节都不解、超限当场断、半截目录不可见、同一摘要不重复取。

**3b-3 · 服务与装载**：`product-ui-server` 按 `/<sha256>/` 出文件；`product-surface`
按项目快照回答并带原因；观察台的测试包改为**真的走一遍这条管线**，而不是直接放进
目录 —— 否则观察台验证的是一条真实程序不走的路。

## 6. 备选方案（为什么不选）

**A. 只走产品包**（照 §18.1）。主路（契约拉取）的产品永远没有界面；带界面的要等
TD-012 的根证书 —— 而 §3.5 说明了界面本来不需要等它。

**B. 契约里写远程 URL**。见 §3.1。

**C′. 契约里写版本号，按 `/ui/{version}` 取**。不选：同一个版本号底下的字节能被
悄悄换掉，而运行时分不出来；那正是 §18.3 专门写了一段去防的事。按摘要寻址让这件事
**不可能发生**，而不是「发生了能报出来」。

**D. 不升契约版本，把 `product.ui` 做成旧运行时能忽略的扩展字段**。做不到：旧运行时
已经是 `additionalProperties: false`，没法回头让它宽容。要让将来的运行时对未知
字段宽容，是另一个题（涉及「未知字段是笔误还是新特性」），本 ADR 不开。

## 后果

- 契约 schema 多一个可选字段、一条规则、一个版本；运行时多一条取回管线与一个
  按摘要的目录。
- **提议期间没有动正文**（与 ADR-022 同一条纪律）。**接受后已同 PR 修订**
  `30-contract-schema.md`：§3（`contract: "0.2"`、`product.ui` 可选）/ §5（`ui` 字段）/
  §15（R17）/ §18.1（`ui/` 目录 → `ui.zip`）/ §19（「UI 资源的技术形态与加载隔离」
  关闭）。
- **顺带补正了两处与本 ADR 无关的漂移**（改正文时看见的）：§3 / §6 的顶层键还叫
  `workspace`（代码早已是 `project`）；§16「完整示例」是一份手抄旧版，十处校验不过
  而文字写着「通过全部规则」。§16 改为与夹具同一份，并加了一条测试从文档里读出来
  校验、与夹具比对 —— 否则它还会再漂一次。
- **正文先于代码**：§3 写的是 `0.2`，而运行时要到片 3b-1 才接受它。与 ADR-022 修订
  §8.2 的次序相同 —— 正文说的是定下来的设计，分片是把它做出来。
- **不再被引用的摘要目录没人清**：一个产品升了几个版本、每版换一次界面，旧的就留在
  盘上。落地时登记一条 TD，等真有体积问题再做回收 —— 回收要看**所有项目快照**，
  不能只看当前版本，删错了就是某个老项目打开时没有界面。
- 本 ADR **不解决**「产品界面出现在项目的哪一块」（今天临时在概览最底下）—— 那是
  产品侧的界面决定，另议。
