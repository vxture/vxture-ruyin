# ADR-012 两级产品供给：契约拉取为主，产品包为辅

- 状态：已接受
- 日期：2026-08-31
- 相关：ADR-003（离线宽限）、ADR-009（能力通路）、ADR-011（框架边界）、
  30-design/30-contract-schema.md §18、60-operations/10-tech-debt.md TD-012

## 背景

§18.3 原本只画了一条路：Registry → 下载 → 验签 → 安装。于是「产品到本地」
被签名信任锚（TD-012）整条挡住——而信任锚依赖尚不存在的 Registry。

先不问怎么装，先问**什么必须在本地**。核心需求只有三件：数据不出域、用本地
文档、产出本地文档。倒推：

| 组成 | 必须本地 | 理由 |
|---|---|---|
| 用户文档、产出文档 | 是 | 这就是需求本身 |
| 文件访问与授权 | 是 | 只有装在本机的东西够得到 |
| 出口门控与审计 | 是 | 管的是「什么离开」，必须在离开之前 |
| 产品契约 | 运行时须在内存 | **但不一定要「安装」** |
| 产品的智能（提示词、编排） | 否 | 在产品自己的能力面（ADR-009 / 011） |
| 模型 | 否 | 产品那一侧接 |

**推论：产品在本地需要的只是一份契约声明**——不到 20KB 的 YAML。产品的智能
不在本地，模型不在本地，所以「安装一个产品」比包管理器那套轻得多。

## 决策

**按产品随附什么，分两级供给：**

| 产品形态 | 本地需要 | 供给方式 |
|---|---|---|
| 纯契约（今天的标书夹具） | 一份契约 | **拉取 + 缓存，不安装** |
| 契约 + 静态资产 | 模板 / schema / 示例 | 产品包 |
| 契约 + 本地技能 | 可执行的连接器 | 产品包 **+ 签名** |

### 一级 · 契约拉取

- **来源**：产品自己的能力面（`GET /products/{id}/contract`）——与能力调用
  同一条通路，不新增依赖，也不新增一处存主机名的地方。
- **校验**：照常过 R1–R13。契约校验是加载期的事，与它从哪来无关。
- **缓存**：按 `product.version` 落盘，多版本并存，可回退。
- **离线**：沿用最后一次拉到的契约——与权益是同一个问题的同一个答案
  （ADR-003）：桌面必然离线，快照可用但不与服务端竞争真相。
- **项目绑定**：项目创建时快照当时的契约（已实现），产品升版不动既有项目。

### 二级 · 产品包

`.ruyinpkg` 管线已实现（zip 护栏、CHECKSUMS 双向校验、原子落盘、多版本并存
与回滚）。**只在产品随附本地资产或本地可执行技能时才需要**；后者一旦成立，
签名不再是可选项——那是在用户机器上跑第三方代码。

## 后果

- **签名信任锚缺失只挡二级，不再挡「产品到本地」这条承接线。** TD-012 的
  阻塞面随之缩小。
- Registry 不是一级的前置条件，「下载」这个缺口的紧迫性下降。
- §18.3 的「Same Package, Any Runtime」需改写：**同一份契约，任一运行时**；
  包只是契约的一种承载方式，不是唯一方式。
- 「不安装」不等于「不留在本地」：契约仍落盘、仍版本化、仍离线可用。区别在
  **获取方式**，不在本地有没有。
