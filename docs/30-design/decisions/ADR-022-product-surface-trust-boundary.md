# ADR-022 产品接入面：沙箱是边界，**裁剪归守护进程**；SDK 是薄的

- 状态：**已接受**（owner 2026-09-10：「接受」）。原方向：「先不要考虑智能体（bid），
  先把基础设施框架建好」—— 四块候选里选了产品接入面
- 日期：2026-09-10
- 事实来源（每条都对过正文或代码，没核到的写「未核」）：
  `30-design/60-technical-architecture.md` §3.6 / §8.1 / §8.2 / G8 / T6 / T11、
  `40-implementation/10-product-integration-guide.md` §6.2 / §6.3、
  `40-implementation/30-harness-dsh-spike.md` §9 两条教训、
  `apps/local-host/src/server.ts`（鉴权现状）、`packages/`（现状清点）
- 相关：ADR-007（workspace 归平台，本地容器是项目）、ADR-011（运行时给事实，产品给
  措辞）、ADR-014（上下文是资料不是指令）、ADR-015（项目必须归属工作区）、
  ADR-021（Ruyin 是环境不是产品）

## 0. 一句话

**沙箱 iframe 是必须的边界，但它不够 —— 契约裁剪要在守护进程里做，凭据要是
产品级的。** 设计正文 §8.2 把裁剪放在 Workspace UI 的桥接层里、对下游携带全局
会话 token；那样守护进程分不出「这次调用来自产品界面」和「来自工作台自己」，
**闸门就不是最后一站**。

## 1. 现状清点（2026-09-10）

| 东西 | 在不在 |
|---|---|
| `packages/product-sdk` | **不在**。`packages/` 只有 cli / contract-schema / document / runtime-core |
| 桥接层 | **零行代码**。全仓搜不到 |
| 产品 UI 沙箱面 | **不在**。`products/bidproposal` 只有一份契约，没有界面 |
| 守护进程鉴权 | **一个全局会话 token**：`server.ts` 里 `auth !== \`Bearer ${deps.token}\`` 即 401，除 `/health` 外**所有端点一视同仁** |

所以今天的处境是：**契约能校验、能加载、能跑任务，而产品自己的界面无处可放。**
任何业务产品要接进来，走的那条路还没有铺。

## 2. 设计正文怎么说的，以及它的一处不足

`60-technical-architecture.md` §8.2：

```text
产品 iframe（sandbox 属性 + 独立 origin + CSP）
        │  postMessage
Workspace UI 桥接层（能力白名单：仅本产品契约声明范围）
        │  携带会话 token
Local API
```

> 产品 UI 能做什么由其契约决定，桥接层按契约裁剪 API 面 ——
> UI 层不可能越出 Tool Gate / 权限模型（G8）。

**沙箱那一层是对的，而且不可省。** 独立 origin + CSP + sandbox 属性，使产品的
界面代码**根本够不到** Local API：它没有 token，跨源也发不出去，只能 postMessage
给父窗口。这是一条真实的边界，本 ADR 不动它。

**不足在下面那一层。** 裁剪发生在 Workspace UI（渲染进程）里，而对守护进程出示的
是全局会话 token。于是：

- 守护进程**分不出**这次调用是工作台自己发的，还是桥替某个产品转发的；
- 「UI 层不可能越出 Tool Gate」这句保障，**强度等于桥那几百行前端代码**；桥里一个
  疏漏就是全量权限，而不是越权一点点；
- 审计里记不下**发起方是谁** —— 而 ADR-014 花了很大力气让每段字节都带着出处。

对照本仓自己写下的判据（`40-implementation/30` §9 两条教训之二）：

> **闸门必须是最后一站。**「决定」与「派发」之间只要还有一站可以改名字或改参数，
> 闸门就只是建议。评估任何外部执行框架时，这一条应当先问。

那条教训是评估外部框架时得出的，但它对自己的桥同样成立 —— **而且更该成立**：
外部框架我们只能选择用不用，自己的桥是我们自己在决定要不要留这个口子。

## 3. 决定（三条）

### 3.1 沙箱照旧，且是硬边界

产品 UI 跑在 sandbox iframe、独立 origin、CSP 白名单；**不给任何特权通道**
（§3.6 第 2 条：Shell 不给产品 UI 特权通道）。产品 UI 拿不到会话 token。

### 3.2 桥对下游用**产品级凭据**，裁剪由守护进程执行

Workspace UI 向守护进程为「这个项目里的这个产品」换一张**短时、按 (projectId,
productId) 限定**的凭据；产品的调用带这张凭据走 `/bridge/*`，**守护进程按该项目
签下的那份契约快照裁剪**。

两条独立的门，缺一不可：

| 门 | 挡什么 | 在哪 |
|---|---|---|
| 沙箱 + 独立 origin | 产品代码直接够到 Local API | 浏览器 |
| 产品级凭据 + 服务端裁剪 | 桥被绕过 / 桥自己写错 | **守护进程** |

守护进程因此**知道发起方**，于是：越权当场拒绝（不是靠桥自觉）、审计记得下是谁
发起的、`/bridge/*` 与 `/projects/*` 是两套面而不是同一套的两种叫法。

**会话 token 与产品凭据互不通用**：拿会话 token 打 `/bridge/*` 拒，拿产品凭据打
`/projects/*` 拒。**两个方向都要拒** —— 只拒一边的话，另一边就是那条没人走过、
坏了也看不出来的路。

### 3.3 SDK 是薄的：它不是权限层

`@vxture/ruyin-product-sdk`（**不是** `@ruyin/product-sdk` —— 接入指南 §6.2 里那个
scope 与本仓四个包的命名不一致，以本仓为准；W5 的发布 ORDER 到时要加它，守卫会提醒）
只做三件事：postMessage 握手、把 §6.2 那七个面（`objects` / `state` / `tasks` /
`checkpoints` / `context` / `results` / `workspace`）包装成类型化调用、把事件投影
出来。

**SDK 里不做任何判断**。产品作者换一份改过的 SDK 就能绕过的东西，本来就不该是
保障。SDK 给的是**便利与类型**，不是安全。

## 4. 不变的（这几条本 ADR 只是重申）

- **控制权界面一律归 Runtime**（接入指南 §6.3）：Checkpoint 呈现与决策、Context Set
  确认、目录授权、同步与冲突、审计查看、登录与设置。**防的是产品自绘一个假的
  确认框** —— 这一条比本 ADR 的任何机制都要紧。
- 产品 UI **读不到上下文条目的内容**，只看得到元数据与绑定状态（§6.2 那行注释）。
  这一条要由守护进程保证，不是由桥保证。
- Tool Gate 三层合成不因为调用来自产品 UI 而变松（G8）。
- 项目必须归属工作区（ADR-015）—— 产品级凭据因此天然是**项目内**的，不存在
  「跨项目的产品会话」。

## 5. 分片计划

**片一 · 信任脊柱（先做这个）**：产品级凭据的签发与校验 + `/bridge/*` 这一族的
存在 + 第一个真实端点 `GET /bridge/context`（**只回元数据**）。

选它打头，是因为**它是唯一能被单独证伪的一片**：不需要任何产品、不需要能力面，
用 `bidproposal` 那份契约夹具就能验四件事 —— 会话 token 打 `/bridge/*` 被拒、
产品凭据打 `/projects/*` 被拒、A 项目的凭据读不到 B 项目、上下文正文一个字都不
出现在 `/bridge/*` 的回应里。

**片二** SDK 包 + postMessage 握手（此时才有东西可握手）。
**片三** 沙箱装载与 CSP（Workspace UI 这一侧）。
**片四** 七个面逐个补齐，每个面各自带服务端裁剪。

**每一片都必须能在没有真实产品、没有能力面的情况下被验证** —— 这条纪律沿用
W7 那一批的做法（`70-workplan` §W7「比这一批更靠前的前置」那一段）。

## 6. 备选方案（为什么不选）

**A. 照 §8.2 原样做：桥在渲染进程里裁剪，对下游用会话 token。**
不选，理由见 §2。补一句公道话：这是浏览器插件化 UI 的**常见做法**，在「产品由
第一方编写」的假设下也够用 —— 但 G8 的原文写的是「未来第三方 publisher」，
那个假设迟早不成立，而到那时改的是信任模型，不是改几行代码。

**B. 干脆不做沙箱，产品 UI 直接嵌进工作台。**
不选：那样产品的一个脚本错误就能把整个工作台带下水，更不用说恶意的情形。
§3.6 已经比较过 Module Federation 与沙箱 iframe，本 ADR 不重开这个题。

**C. 让产品 UI 直接持会话 token 调 Local API，省掉桥。**
不选，且这一条是**明确禁止**的：那等于把整台守护进程交给产品代码。

## 后果

- **`60-technical-architecture.md` §8.2 已随本 ADR 一并修订**（同日接受）：那张图的
  第三行由「携带会话 token」改为产品级凭据，并写明裁剪在守护进程。**提议期间没有
  动正文** —— 一份还没被接受的 ADR 去改它想改的正文，等于自己给自己背书。
- 守护进程多一套凭据的生命周期（签发、过期、随项目关闭作废）。这是实打实的成本，
  换的是「闸门在守护进程里」。
- `40-implementation/10` §6.2 的包名已更正为 `@vxture/ruyin-product-sdk`（同日）。
- W5 的发布 ORDER 到时要加 `product-sdk`（`check-publish-order.mjs` 会提醒）。
- **本 ADR 不解决**「产品的界面从哪来」：一级供给是契约拉取（ADR-012），而契约里
  今天**没有 UI 入口字段**。那是片三要面对的题，届时另立。
