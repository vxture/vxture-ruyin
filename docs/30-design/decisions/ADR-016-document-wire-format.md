# ADR-016 结构化文档：上线格式是 Markdown，内部表示是 mdast，来源按路径给

- 状态：已接受
- 日期：2026-09-01
- 相关：ADR-013（成果落盘：C 为主）、ADR-006（skill 归 Ruyin）、ADR-011（框架边界）

## 背景

ADR-013 定了「提供方返回结构化内容，Runtime 渲染为目标格式」，但没有定这份
结构化内容**长什么样、怎么过线**。M2 只交了字节落盘的接缝，C 的主体一直空着
（TD-019）。

空着的代价是具体的：契约里的 `export_result` 声明了 `docx / pdf`，宿主一个
都没实现，于是 `toolOffers` 把它从工具面上安静地摘掉，`export_deliverable`
这个任务**没有任何办法达成它的目标**——它会烧满 12 个模型回合，然后报一句
「exceeded 12 turns without producing a result」。

## 决策

### 一、内部表示用 mdast，不自造 schema

mdast 是 Markdown 的标准 AST（unist 家族），有规范、有一整套现成工具。自造
一个只有本仓认识的文档 schema，等于让每一个下游渲染器都变成本仓的负债；而
mdast 的节点表（heading / paragraph / list / table / blockquote / code）恰好
就是 ADR-013 说的那些「文档结构的形状」。

按 ADR-011 的自查判据：定义的是「有什么」，不是「怎么说」。内容全部来自产品。

### 二、上线格式是 Markdown 文本，不是手搓的 AST JSON

理由不是「方便」：

- 模型写 Markdown 是母语；写大段嵌套 JSON AST 会在结构处出错，而错在结构上
  的文档，渲染出来是错的但看不出来。
- 同一篇文档的 JSON AST 表示大约是 Markdown 的三到五倍 token。

**这不违反 ADR-013 对 A 的否决。** A 被否的理由是「字节流经对话」——一份
2MB 的 `.docx` 变成 2.7MB base64 塞进上下文。而正文本来就必须流经对话：**是
模型在写它**。真正的分界是：

> A 让模型转运一份它并没有创作的字节；C 让模型交出它本来就要创作的正文。

一份 `.docx` = 正文 + 几十倍于正文的 OOXML 包装 + zip 容器。包装那部分不该
过模型，正文那部分躲不掉。

### 三、Markdown 说不了的，用 `remark-directive` 指令，不发明语法

分页、目录域这类正式文档必需、Markdown 没有的概念，走 `ry-` 前缀的指令：

```markdown
::ry-pagebreak
::ry-toc{depth=2 title=目录}
```

指令是 Markdown 生态里既有的扩展机制。名字用**连字符**不是风格选择：
`::ry:pagebreak` 会被解析成一个普通段落加一个行内指令，于是 `::ry` 以字面
文本印进标书，而分页根本没发生——**解析器不报错，成品看起来也正常**。所以
诊断表里专门有一条抓它。

### 四、渲染的来源按**路径**给，不把正文贴进调用参数

`export_result{path, format, sources: [路径…]}`。这些文档上一轮已经由
`write_document` 写在授权目录里了；把正文再贴进调用参数，等于让整篇文档
第二次流经对话、按全价计费，去产出一份本来就在磁盘上的东西。

模型决定的是**哪几份、按什么次序**——那是只有它知道的部分。

### 五、丢内容就失败，不交「少了点东西」的成品

渲染器表达不了的构件（图片、脚注、HTML、未知指令）分两级：

- **lossy**：内容到不了成品 → **拒绝渲染**，回带行号的具体原因
- **degraded**：内容在，保真度降了 → 照渲，但把降级说出来

一份悄悄少了图表的标书，长得和一份正确的标书一模一样，而没人会发现——直到
它就是交出去的那一份。改一版重来的代价是一个回合；不改的代价是这次投标。

### 六、契约只声明宿主真渲染得出来的格式

`export_result` 的 `format` 枚举收到 `[docx]`。声明一个没人实现的格式，就是
这条工具原本的那个毛病：契约里有、宿主没有、任务因此无路可走。

## 后果

- 新增发布包 `@vxture/ruyin-document`（表示 + 渲染器）。同构（用
  `Packer.toArrayBuffer` 而非 Node Buffer），Cloud Runtime 直接复用。
- 引入本地依赖：`unified`/`remark-*`（解析）与 `docx`（OOXML 生成）。ADR-013
  说过渲染引入依赖与「不为解析引入本地库」不冲突，因为那条针对的是**模型
  能力**。选型偏向生态标准而非自研，代价是供应链面变宽，由 `audit` 关口守。
- **PDF 未落地**。Electron 壳里已经有 Chromium（`printToPDF` 是现成的高质量
  渲染器，零新依赖），但守护进程与壳是两个进程，跨进程渲染是一项独立的架构
  决定，不塞进本条。见技术债登记。
- 声明了本宿主跑不了的工具的任务，`startTask` **当场拒绝**并说清缺什么，
  任务列表也提前禁用。同一条判据（`unrunnableTools`）两处共用，避免漂移。
