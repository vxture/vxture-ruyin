# ADR-004 能力供给边界：模型与 skill／连接器不由 Ruyin 提供

- 状态：**部分被 [ADR-006](ADR-006-skills-on-harness.md) 取代**（2026-08-31）
  - **仍有效**：模型推理由 Atlas 供给，Ruyin 不实现推理、不计量推理；闸门留在本地。
  - **已作废**：skill／连接器由 Runos 供给并受订阅约束。改为由 Ruyin 自建于
    Harness 之上，**权益门控只到产品级**，skill 不受权益限制、不单独计费。
  - **理由亦随之修订**：本文把 R6 归因为「解析取决于订阅」；ADR-006 改回
    「契约须在两个运行时跑出一致行为，故不能绑定任一宿主的供给实现」。
- 日期：2026-08-31
- 相关：ADR-001（能力通路）、ADR-003（离线宽限）、
  30-design/30-contract-schema.md §15（R6）、30-design/40-context-architecture.md §4.2、

## 背景

Runtime 要兑现产品契约声明的需求，但「兑现」不等于「自己实现」。此前的能力
清单把推理调用与连接器一并列为 Ruyin 能力，导致把「局域网／私有服务连接器」
当成 Ruyin 的开发项排期 —— **方向是错的**。

## 决策

能力面分两类，边界按**「是不是只有装在用户机器上才做得到」**划：

**甲类 · Ruyin 自有**（别人做不到）
本地文件接触、项目容器与本地存储、任务编排（Harness）、工具过闸（Tool Gate）、
人在回路、出口门控与审计、成果与导出、身份与权益接入。

**乙类 · 订阅得来**（Ruyin 只做接入、门控、留痕，**不提供**）

| 能力 | 供给方 | Ruyin 的职责 |
|---|---|---|
| 模型推理 | **Atlas**（唯一 LLM 出口、唯一推理计量入口） | 解析、发起、并入执行循环；过传输门、落审计。**不实现推理，不计量推理** |
| skill / 连接器 | **Runos**（消费面走 MCP） | 发现、过闸、执行、并入循环。**不自建连接器生态** |

Ruyin 内建的连接器只有 `local-fs`（本机文件，别人够不到）；其余按 MCP 接入。

## 后果

- **「LAN／私有服务连接器」不是 Ruyin 的开发项**，是 Runos 的 skill，经订阅到达。
  此前按 P1 排期的判断作废。
- **R6 的真正理由由此确定，并应写进设计文档**：能力解析到哪、能不能用，取决于
  **用户订阅了什么**。产品发布时不知道将来哪个用户买了哪一档，因此**没有资格把
  提供方写死**——写死就绑在了发布当天的供给格局上。R6 不是洁癖，是订阅模型的必然。
- 契约 `context.types[].sources` 的 `lan` / `private` / `external` 取值由此得到解释：
  产品声明**要什么来源的资料**，由哪个连接器供给是订阅与解析的结果。
- **闸门必须留在本地**：门控发生在数据离开之前，这条不因供给方在云端而改变
  （与 ADR-002 循环归属同源）。

## 待定

- **Runos 怎么够得到。** 其消费面走 MCP 且要 S2S 鉴权，而 Ruyin 是零密钥 public
  client——与 Atlas 同一个结构性障碍（ADR-001）。同一个解（经业务产品服务端）
  能否覆盖**本地资源连接器**需另行判断：云端够不到本机文件与局域网，那部分
  连接器必须在本机执行。
