## 首轮执行结果

证据在本机工作目录 `v0/`（本会话可视化目录下），客户模板和生成稿不提交 Git。

### 包与宿主

执行 `node scripts/dev/bid-v0-package-probe.mjs <output>`：真实标书契约升级到 0.2，钉界面摘要，包内加入 `ui.zip`；CLI 打包并在临时库安装。结果 `installed=true`、`packagedUi=true`、`uiReady=false`。根因：安装器只解产品包，界面加载器读取另一处摘要目录，现有界面取回依赖独立 fetch 管线。下一步复用该解包校验能力接通包内界面，不能靠复制目录假装安装成功。

已有产品桥只支持项目元数据、任务启动和结果，没有 Markdown 保存或 Word 试排。接入编辑功能需要最小宿主文档接口，必须先登记接口契约。

### 排版

24 段合成长文，在公司模板、另一份书签模板、公司模板依次试排：22.16 秒 / 51 页、9.82 秒 / 3 页、54.90 秒 / 51 页。均生成 DOCX 和 PDF，原件摘要保持一致。人工查看公司模板第 38–41 页：正文跨页、原有页眉页脚、后续章节保留。发现并修复章节跳转取末页而非起始页的问题。

Markdown 表格和图片输入明确拒绝；当前只接受纯文本段落和平面列表，因此不能按完整标书排版验收通过。保留模板原有表格不等于支持生成新表格。

### 执行与 DeepSeek

runtime-core 96 项测试通过（含验证修订、审批和恢复），但使用模拟网关，不计实际模型写作效果。

SDK 使用 `@deepseek-ai/dsh-sdk-client@0.2.2-rc.4`，安装在隔离工作目录并跳过依赖安装脚本。该版本可从 npm 显式获取，默认 dist-tag 指向旧版本；应固定精确版本和 lockfile。未将这些依赖加入 RUYIN。

用 SDK 的 `sdk-minimal` profile 和清理后的进程环境启动，只设置合成工作目录，未调用模型。握手和会话工作目录读取成功，关闭后 `resumeSession` 返回 not found。空会话未形成足够的可恢复持久状态，此项不据此判定上游缺陷，也不计恢复通过。其默认持久 Shell 不适合直接进入标书产品，后续必须用自定义工具组合和宿主审批桥验证。

## 第二轮实施登记（2026-11-18）

沿用已获授权的仓库登记方式。先补齐离线包内 UI 的统一校验和激活；嵌入 UI 与下载 UI 使用相同摘要、大小、ZIP 路径护栏。

新增最小宿主文档接口（待同步 RY-102）：产品桥 GET /bridge/documents/:id 返回 {id, markdown, revision}，不存在返回 404；PUT 同路径接受 {markdown, revision}，创建以 revision=0，更新必须匹配当前版本，否则 409。不接受项目路径，项目与产品取自桥凭据。id 限定为 1–80 位字母数字下划线连字符，正文上限 1 MiB。文档保存在项目 SQLCipher 库，不写明文临时文件。接口只管理产品生成的 Markdown，不开放参考材料读取。

## 第二轮验证结果

### 已关闭的技术缺口

- 离线包内 ui.zip 在 preflight 和安装时校验契约摘要、大小、ZIP 条目和根入口，复用 ui-fetch 的同一校验函数。篡改 UI 即使重算外层 CHECKSUMS 也不能安装。已通过真实产品静态服务器 HTTP 200 检查。
- 宿主文档桥接入项目 SQLCipher 数据库，具备乐观版本控制；过期版本更新返回 409。测试关闭全部数据库连接后重新读取，正文仍在；项目 A 请求中伪造项目 B 不会跨界，另一产品也读不到该正文。磁盘扫描找不到合成明文标记。
- 在 RUYIN 工作台中装载真实 .ruyinpkg 的技术探针页面，输入人工编辑内容、保存为 v1、刷新整个工作台后显示“已读取 v1”，正文一致。这是安装/编辑桥验收，不代表标书业务页面完成。
- Markdown 模板试排新增普通 GFM 表格、独立段落 PNG/JPEG 图片。图片限定在 Markdown 目录内，拒绝远程 URL、越界真实路径、伪图片、超过 8 MiB 的图片；不支持的格式仍明确拒绝，不静默丢失。

## 第三轮结果与 V0 技术结论（2026-11-18）

负责人补充模型凭据后，原“无可用模型路由”阻塞解除。以下是实际网络调用结果，未使用模拟网关。

### RUYIN 真实模型批次

执行 opt-in 探针 scripts/dev/bid-v0-model-probe.mjs，以两个独立 Node 进程运行同一 ProjectRuntime/SQLCipher 项目，使用现有 LocalModelGateway 对接官方 deepseek-flash：

1. 第一进程完成 REQ-01 章节，REQ-02 完成推理后停在人工检查点，然后退出。
2. 第二进程从持久库恢复同一 REQ-02 检查点，确认后继续。恢复操作没有重新请求已完成的模型回合。
3. 完成 REQ-03，给第一章增加一条人工编辑；独立重写第二章，新增“每周抽检”和“抽检记录”。
4. 重写先保存为候选文档，采纳前正式第二章不变；采纳后第一章（含人工编辑）和第三章逐字不变，过期版本覆盖被拒绝。审计链校验通过。

证据 v0/live-model/model-result.json：3 章、4 次模型回合、独立进程恢复、0 次回放模型调用。恢复验证的边界是**已提交模型回合的检查点**；不声称支持强制杀进程后的未提交流式 token 原地续写。探针内的批准仅代表自动化测试动作，正式页面仍需用户确认候选内容。

实际生成的第二章正文又进入公司模板试排，成功生成 48 页 DOCX/PDF，原模板摘要不变；已目视检查第 38 页正文继承模板版式。章节标题映射到模板现有槽位，原始 Markdown 保留，正文映射副本单独保存。证据在 v0/live-model/word-output/。

### DeepSeek Harness 完整执行与恢复

执行 scripts/dev/bid-v0-sdk-probe.mjs，依赖仍在隔离目录，精确版本 @deepseek-ai/dsh-sdk-client@0.2.2-rc.4。采用 sdk-minimal 加独立 patch，禁用 Shell、文件与工作目录工具，并把文件策略设为 read-only；环境仅传递基础系统变量及本次模型凭据，不继承其他应用的令牌。

第一轮完成合成巡检方案写作，保存会话后完整关闭 SDK 子进程。新建 Harness，通过 resumeSession 恢复，并要求模型回忆仅在第一轮提供的合成核验码；准确返回 V0-QS-742。两轮 finishReason 均为 completed，事件中无工具调用。证据 v0/sdk-live/sdk-live-result.json、first-events.json、restore-events.json。此前空会话 not found 的结论已由本次有实际回合的恢复验证补齐。

SDK 可借鉴的生命周期、通知订阅和显式恢复接口已有执行证据；正式执行器仍优先沿用 RUYIN 内核和宿主授权，不因探针通过就引入另一套框架。仅文本配置不等于完成业务工具适配或 OS 沙箱验证。
