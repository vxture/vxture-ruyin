# Product resource library P8.1

Registered 2026-11-20 under the standing local RY registration exception. This is a minimal generic runtime addition for the authorized enterprise-material MVP, not a new knowledge platform. The product owns categories and its library UI in its installed package; the host owns storage and scope enforcement.

## Local RY-102 addendum

- Authenticated host GET /products/:id/library-surface returns availability and the installed package library.html entry on the existing isolated product origin. POST /products/:id/library-token mints a separate short-lived credential bound to the current workspace and installed active product. It cannot be used on project /bridge or host routes.
- /library-bridge uses only library credentials and rechecks active workspace and active product per request. GET /items lists metadata; POST /items imports explicitly selected file bytes as {name,category,base64,id?,expectedVersion?}. Supported PDF/DOCX/MD files are limited to 20 MiB. Category is an opaque product field, not a host business enumeration. Updates append immutable versions; stale expectedVersion fails. GET /items/:id returns all version metadata. GET /items/:id/versions/:version/units/:index returns saved reading blocks. POST /items/:id/versions/:version/retry starts another local reading snapshot while preserving old blocks.
- Project bridge GET /library lists current-workspace/product resources. GET /library-selection lists the project's pinned resources. POST /library-selection {id,version,revision} copies the selected immutable source and reading blocks into that project and records the origin. DELETE /library-selection/:id {revision} removes only the selection, retaining library originals and project snapshots. Host aliases under /projects/:id/library and /projects/:id/library-selection serve the project configuration UI. A pin requires a completed snapshot; repeated pin of the same version is idempotent. Pinning another version explicitly changes selection, preserves old source copies and never rewrites generated chapters.

No caller-supplied workspace or product field can change token scope. Original bytes and metadata use the existing encrypted storage and key hierarchy in a distinct libraries directory; library containers are not runtime projects and do not appear as business projects. Reading uses the existing local reader and durable reading implementation. No model call is made in P8.1. Runtime restart preserves completed versions and makes interrupted reading retryable.

Use synthetic materials; no company folders or secrets are implicitly imported. Keep existing projects and task history intact. P8.2 extraction/recommendation, P8.3 writing integration and P8.4 review remain separate.
