## 标书产品双运行时方案

一个产品源码、一个业务契约、两个部署入口。共用需求矩阵结构、证据定位、章节生成、覆盖校验、文档渲染和业务验收样例。产品 UI 优先共用组件，通过宿主连接层分别接浏览器与 RUYIN 工作区。产品实现独立于 RUYIN 仓库内的样例。

- 云端入口：由云端宿主处理租户授权、文件和产物存储、任务执行、推理与导出。先验证宿主是否已具备这些接入点；新产品不自建历史能力回合端点。
- 本地入口：分发 `.ruyinpkg`，由 RUYIN Local Runtime 运行。同一套业务逻辑只使用宿主提供的文件、解析、检索、推理和输出能力。严格不出域模式须使用本机或客户域内模型；模型不可用时停止，不回退到公网。招标内容及其派生数据不得进入域外推理、检索、日志、遥测或同步。
- 首条双端验收链路：导入同一份脱敏招标文件 → 生成有来源引用的结构化需求矩阵 → 校验 → 人工确认具体版本。双端共享同一组业务验收样例；桌面额外验证重启恢复和域外连接阻断，云端额外验证租户隔离。

## 首轮页面与执行设计

### 标书正文与预览决策

- 模板库属于工作台产品能力，支持导入用户拥有的 Word 模板、查看预览、配置章节与样式映射、验证并发布模板版本。项目选定并锁定一个版本；模板更新不会改变已有项目，迁移须重新检查映射并重新排版。客户域内的模板与映射留在客户域内。
- 模板映射区分固定内容与可替换槽位；优先使用内容控件或书签，旧模板可通过人工确认的章节位置建立映射。缺失、重复或不受支持的槽位须在试排时报告，不覆盖原模板。公司提供的文件只用于首轮验收，产品不依赖其路径、章名或特定编号。

整改首片：使用现有 Markdown 解析器，将技术路线的段落与平面列表映射到公司 Word 模板的空正文位置。从同一次 Word 排版保存 DOCX 并导出 PDF，用本地浏览器展示同一份 PDF。复杂构件留待后续映射，不静默丢弃。

模板管理首批：把试排目标改成用户确认的唯一章节标题或 Word 书签。第二份不同结构的模板验证映射、原件保留和 PDF 排版，随后接桌面模板库界面。

模板库开发验证：本地保存模板副本、内容摘要和章节映射；按不可变版本解析试排输入。先用开发命令验证导入、重开和试排，不增加宿主 API。

MVP 纵切片：一个模板、一个章节、一个 Markdown 编辑区。直接调用已验证的 Word 试排脚本，PDF 预览和 DOCX/PDF 下载使用同一版产物。开发预览只监听本机，先验收编辑到导出；正式产品包与 RUYIN 内容区的绑定由同一流程接入，不新增后台体系。

MVP 恢复批次：可指定本机工作目录保存 Markdown 和最近一次排版状态，重启后继续；临时模式仍明确提示结束后清除。项目编辑桥尚不支持正文保存和试排，不能用独立服务伪装为已接入产品包。

- 标书正文全程以按章节版本化的 Markdown 为唯一编辑源。总体目录、招标需求映射、模板配置和图片资源单独管理；候选重写只产生目标章节的新版本。DOCX、PDF 是交付产物，不回写 Markdown，不依赖 Word 插件来日常编辑。
- RUYIN 内容区内提供即时 Markdown 预览，以及由实际排版引擎生成的分页预览。即时预览不承诺与 Word 页界一致；正式预览由同一 Markdown 快照、模板版本、资源和排版引擎生成。预览与最终交付复用同一快照及排版结果；文档一旦改动，旧预览标记为过期。
- 桌面优先使用公司投标模板的副本，由现有 Markdown 解析与样式映射生成临时排版稿，原生 Word 计算目录与分页并渲染 PDF，工作台内嵌查看。用户导出时才保存所选的 DOCX 或 PDF；生成分页预览所需的中间文件仅在客户域内临时保留。无 Word 的环境须单独验证替代排版引擎及标明预览基准。
- 验收使用真实模板：对比浏览器分页预览、原生 Word 打开和导出 PDF 的页码、分节、长表格表头、题注及目录；记录字体或 Office 版本变化导致的差异。参考 DeepSeek Harness 的页面渲染和布局检查流程，复用可用的渲染能力。

桌面 Word 验证批次：使用合成技术标测试 Word 原生内容控件的章节定位、候选重写和版式保留。先验证原生文档操作，再决定插件 API；不改本地宿主 API。章节重写以已确认目录为基准，长章节内部按上下文预算拆批，持久化每批结果，供失败重试与独立重写。

- 外层使用现有 RUYIN 工作台：标题栏、全局导航、项目切换和通用任务界面由宿主管理。标书只在项目的产品内容区提供业务步骤和页面，不重复创建品牌栏、项目导航或运行环境切换。在线入口同样复用产品内容，云宿主外层复用现有 RUYIN 布局，外层接入尚待验证。
- 文件页展示导入、解析和失败恢复；矩阵页左侧筛选需求，右侧显示来源文件、页码、条款和摘录。固定的审批区显示当前版本、未核对项和下一步；创建修订版后进入待复核。章节编写、覆盖与导出留作后续阶段。
- 参考 DeepSeek Harness `ca33fd6` 的 turn/step 和 session 事件拆分：屏幕实时进度可丢弃，持久事件只记录可用于恢复或审计的事实（解析完成、矩阵修订、校验结论、审批决定）。运行时继续掌管任务状态和审计，避免把完整招标内容复制到事件日志。
- 组件优先复用 RUYIN Harness、Tool Gate、模型网关和 DOCX 渲染；用 DeepSeek SDK 自定义 profile 做离线开发对照，分别验证只注册业务工具、模型走宿主网关及中断可恢复。其默认 SDK 和 SDK minimal 工具集不直接嵌入正式产品。候选执行器通过测试后才进入部署决策。
- 业务契约中引用使用文档版本、稳定条款 ID、页码或段落锚点及摘录。自动检查引用和版本，人工确认语义歧义。审批自带矩阵修订标识，后续写作按该标识取已确认版本。
