## Owner boundary clarification, 2026-11-20

This supersedes the earlier plan to centralize Atlas model calls in RUYIN. Atlas calls belong to each agent's integration/SDK and should not be relayed through RUYIN. Hosting a generic task loop/background worker does not transfer business prompts, model selection or inference transport ownership to the workbench. RUYIN shows provider metadata and supplies lifecycle, project storage, scheduling, authorization and local tool facilities.

Runos has two distinct uses: cloud applications call the platform's capabilities; desktop applications use locally installed supply compatible with Runos contracts, including a possible future local sandbox. The cloud service itself is not silently installed wholesale on a customer PC. A remote catalog is not proof of installed local supply. Keep local-only routing strict and do not substitute cloud execution for missing local tools.

The existing host contract-task gateway is a compatibility path, not the target Atlas adapter. Its mock-output fallback is being disabled, but it must not mark every product unavailable just because the host has no model configured. No new Atlas relay, direct-client token flow, local arbitrary-code execution or cloud Runos execution was enabled in this batch. Current Atlas exposes S2S-only inference; an agent-owned cloud backend can use that protocol, while a desktop direct adapter still needs an approved public-client/delegation flow. No confidential-client secret or downstream service token is placed in the renderer to bridge this gap.

Private model scope clarification: host model configuration is only for the user's own models, a paid capability outside the current rollout. The owner explicitly chose to keep the existing "private model service" block, name, status descriptions and logic unchanged. Do not replace it with a new planned-feature panel, rename it or add new setup paths in P12. Displaying Atlas metadata and agent-owned Atlas calls are separate from that optional paid feature.
